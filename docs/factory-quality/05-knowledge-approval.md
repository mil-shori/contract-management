# チケット #05: ナレッジ承認・マニュアル生成

## 大原則：自動公開はしない

**AIが起案した誤ったマニュアルが現場に出るのは、マニュアルが無いより悪い。**

- 現場は「システムが言っているから正しい」と受け取る
- 一度でも間違いが出ると、その後すべての内容が疑われる
- 承認は**社長（`owner` ロール）だけ**が行う

`status: approved` になったカードだけが、ボットとマニュアルに出る。

---

## 承認画面の設計

**1画面1カード。承認 / 修正 / 破棄 の3択。**

iPad で**3分に20枚さばける密度**で作る。これが達成できないと、承認が溜まって仕組みが止まる。

```
┌─────────────────────────────┐
│  [動画サムネイル]  ▶ 2:12〜2:48 │  ← タップで該当秒数から再生
├─────────────────────────────┤
│ 「充填後の重量チェックは       │
│   3個連続で見る」             │
│                              │
│ 見る観点: 充填量のばらつき     │
│ 判断基準: 規定±2g を3個連続    │
│ なぜ:  去年ここで          │
│        ロット丸ごと廃棄した    │
│                              │
│ 発言原文:                    │
│ 「3個続けて見ないと意味ない    │
│   んですよ。1個だとたまたま…」  │
├─────────────────────────────┤
│  [破棄]    [修正]    [承認]   │
└─────────────────────────────┘
```

### 並び順

1. `confidence` が低いもの
2. `why` が空のもの
3. 同じ設備・工程の既存カードと**矛盾する可能性があるもの**（埋め込みの近傍で検出）
4. 残り

**矛盾の検出は重要。** 「前に言ったことと違う」は本人にしか判断できず、
放置すると現場が混乱する。

### 修正モード

- その場でテキスト編集できる（特に `criteria` と `why`）
- 音声で修正を吹き込める（それ自体が新しい `capture` になる）
- 修正して承認したものは `version` が上がり、`versions` サブコレクションに旧版が残る

---

## バージョン管理

```
cards/{cardId}                  ← 常に最新版
cards/{cardId}/versions/{v}     ← 旧版（変更理由つき）
```

```jsonc
// versions/{v}
{
  "version": 2,
  "snapshot": { /* そのときのカード全体 */ },
  "changedAt": "timestamp", "changedBy": "uid",
  "changeReason": "冷却時間を15分→20分に変更（8月の温度上昇対応）",
  "announcementCaptureId": "cap_..."     // ← 「なぜ変えたか」の動画（#01 §6）
}
```

**カードは削除しない。** `archived` にする。削除すると #01 §6 の変更管理が成立しない。

## マニュアル生成

承認済みカードから、2種類の出力を作る。

### A. 現場掲示用（1工程1枚）

- その工程の `procedure_step` カードを順に並べる
- **写真＋ピクトグラム＋短い母語テキスト**（#01 §2）
- PDF 出力してラミネートし、工程に貼る
- QRコードを載せ、読むと動画版に飛ぶ

### B. タブレット表示用

- カード単位でそのまま表示
- 各カードから**元動画の該当秒数**に飛べる
- 母語切り替えは `translations` を出し分けるだけ

### 翻訳

- カード単位で Claude に翻訳させる（`translations` フィールド）
- **原文（日本語）を必ず併記する。** 翻訳が誤っていたときに気づける
- 翻訳もレビュー対象にする。ブリッジ人材（#01 §5）に見てもらう

---

## 承認の運用

| 項目 | 決めごと |
|---|---|
| 承認する人 | 社長（`owner`）。品質責任者に委譲する場合はロールを付与 |
| 頻度 | **週1回・30分**を固定枠で取る。溜めない |
| 未承認が溜まったら | 収録を止める。承認できない量を録っても意味がない |
| 承認済みカードの棚卸し | 半年に1回、`archived` 候補を洗い出す |

**承認が律速になる設計を最初から前提にする。** カードを大量生成する仕組みではなく、
「承認できる量だけ録る」仕組みにする。

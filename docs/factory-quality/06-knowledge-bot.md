# チケット #06: iPad ナレッジボット

## 何をするものか

現場で困ったときに iPad から質問すると、**承認済みの社長の観点をもとに**答える。
「一般的な食品衛生の正解」ではなく、**この工場のやり方**を答えるのが存在意義。

---

## 1. 検索（RAG）

```
質問
 ↓ 埋め込み生成（Vertex AI text-multilingual-embedding-002）
 ↓ Firestore findNearest(COSINE, limit=12) ※ status=approved のみ
 ↓ 工程・設備でフィルタ（今いる場所の情報を優先）
 ↓ Claude に「カード＋出典」を渡して回答生成
回答（出典つき）
```

- **チャンク＝カード1枚。** カードはもともと小さいので、追加のチャンク分割が要らない
- 質問者の**現在の工程・担当設備**を検索のフィルタに使う。
  「充填機のことを聞いている人には充填機のカードを優先」
- 多言語モデルなので、**ベトナム語で聞いて日本語のカードを引ける**

---

## 2. 回答生成

```python
message = client.messages.create(
    model="claude-opus-5",
    max_tokens=4000,
    thinking={"type": "adaptive"},
    output_config={"effort": "high"},
    system=[
        {"type": "text", "text": BOT_SYSTEM_PROMPT,   # 役割・原則・禁止事項（付録B）
         "cache_control": {"type": "ephemeral"}},
    ],
    messages=[{"role": "user", "content": build_context(cards, question)}],
)
```

### 回答の必須要件

1. **必ず出典を出す。** カードID・元動画のタイムコード・誰の発言か
2. 出典から**動画のその秒数を再生できる**。「社長がこう言っていた」を確認できることが信頼を作る
3. **根拠が無いことは答えない**（次項）
4. 質問者の言語で答える。原文（日本語）も併記する

---

## 3. 「わからない」と言わせる ← この仕組みが枯れない理由

**承認済みカードにヒットしない質問には、答えさせない。**

```
「その件はまだ整理されていません。
　社長に確認してから回答します。（質問を記録しました）」
```

- 質問は `knowledgeGaps` に積む（#02）
- **同じ趣旨の質問が何回来たかを数える**（`askedCount`）
- 承認画面に「質問が多い未整備テーマ」として出す
- **それが次に録るテーマのリストになる**

```
ボットが答えられない → 質問が溜まる → 何を録るべきか分かる
      ↑                                        ↓
   カードが増える  ←  承認  ←  カード起案  ←  録る
```

**ここでループが閉じる。** 「何を録ればいいか分からない」で止まる仕組みにしない。

一般知識で埋めさせると、この循環が働かないまま、もっともらしい嘘が現場に出る。

## 4. iPad の UI

### 入力

- **音声入力は iPadOS のキーボード音声入力で十分。実装ゼロ。**
  独自の音声認識を作らない
- テキスト入力欄は大きく。手袋で押せるサイズ
- **よく使う質問のショートカット**をタイル表示：
  「この設備の点検項目」「異常時の連絡先」「今日の工程の注意点」

### 出力

- 回答は短く。長い回答は現場で読まれない
- 読み上げ：Web Speech API の `SpeechSynthesis`。多言語音声が必要なら Cloud TTS
- 出典は折りたたみ。開くと動画が該当秒数から再生される

### 場所の把握

- 起動時に「今どの工程にいるか」を1タップで選ばせる（または工程ごとの端末で固定）
- これが検索フィルタになり、回答精度が大きく上がる

## 5. 会話ログ

```jsonc
// botSessions/{id}
{
  "userId": "uid", "processId": "proc_...",
  "turns": [ { "question": "...", "answer": "...",
               "citedCardIds": ["card_..."], "answered": true } ],
  "language": "vi",
  "createdAt": "timestamp"
}
```

**ログは改善のために見る。** 個人の評価には使わない（#08）。

見るべきもの：
- `answered: false` が多いテーマ＝ナレッジの穴
- 同じ人が同じ質問を繰り返している＝教育の穴、または回答が分かりにくい
- 特定の工程からの質問が多い＝その工程の手順が不十分（#01 §7）

## 6. やらないこと

| やらないこと | 理由 |
|---|---|
| 一般的な食品衛生知識で答える | この工場のやり方と違う可能性がある。信頼を一度失うと戻らない |
| 承認前のカードを使う | #05 の大原則 |
| 個人の評価に使う | #08。監視ツール化した瞬間に使われなくなる |
| 緊急時の判断を任せる | 異物混入・体調不良・設備停止は**人にエスカレーション**。ボットは連絡先を出すだけ |

**緊急時のエスカレーションは明示的に設計する。** 特定のキーワード（異物、けが、停止、異臭）を
検出したら、回答より先に「すぐ〇〇さんに連絡してください」を大きく出す。

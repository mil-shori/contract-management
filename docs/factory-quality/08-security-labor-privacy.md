# チケット #08: セキュリティ・労務・個人情報

## なぜ独立したチケットにするか

このシステムは**従業員の姿と声を継続的に記録する。**
技術的に動くことと、運用してよいことは別。ここを曖昧にしたまま始めると、後戻りできない。

---

## 1. 個人情報の取り扱い

### 何が個人情報にあたるか

| データ | 扱い |
|---|---|
| 顔が映った動画 | **個人情報**（個人識別符号を含みうる） |
| 音声 | **個人情報**（声紋） |
| 文字起こしテキスト（氏名を含む） | 個人情報 |
| 突合結果・フラグ | **要配慮に近い扱いをする**（評価につながりうる） |

### 決めるべきこと

- [ ] 利用目的の特定と明示（「品質改善と教育のため」）
- [ ] 保存期間（#03 のライフサイクルルールと**必ず一致させる**）
- [ ] 閲覧権限（`manager` 以上と本人のみ。#02 の Rules で技術的にも担保する）
- [ ] 第三者提供の有無（原則なし。クラウド事業者への委託は明記）
- [ ] 本人からの開示・削除請求への対応手順
- [ ] 退職者のデータの扱い

---

## 2. 同意の取り方

- **書面で取る。口頭やなし崩しにしない**
- **母語版を用意する。** 日本語だけの同意書は、実質的に同意を得たことにならない
- 同意書に書くこと：
  - 何を録るか（動画・音声）
  - 何に使うか（品質改善・教育。**人事評価には使わない**）
  - 誰が見られるか
  - どれくらい保存するか
  - **自分の記録を自分で見られること**
  - 同意しない場合の代替手段（紙のチェックリストなど）と、それによる不利益がないこと

### 同意しない人への対応

**代替手段を必ず用意する。** 同意を事実上強制する形にすると、
同意の有効性そのものが問われる。紙のチェックリスト＋対面確認で運用できるようにしておく。

## 3. 労務上の線引き

| 決めごと | 理由 |
|---|---|
| **AIのフラグは懲戒の一次証拠にしない** | 誤判定がありうる。人の確認を必ず挟む |
| **人事評価に使わない** | 評価に使うと、記録が防衛的になり品質改善に効かなくなる |
| **常時監視はしない** | 作業者が録る瞬間だけ。固定カメラの常時録画は今回採らない |
| **記録は本人にも開示する** | 監視ではなく鏡（#01 §8） |
| 就業規則への記載 | 記録の実施・目的・範囲を就業規則または個別規程に落とす |

**労働組合または従業員代表がいる場合は、導入前に説明する。**

---

## 4. アクセス制御（技術）

| 層 | 対策 |
|---|---|
| 認証 | Firebase Authentication。既存 `AuthContext.tsx` のパターンを流用 |
| 認可 | カスタムクレームで `worker` / `manager` / `owner`（#02） |
| Firestore | Rules で本人以外の `workReports` を読めなくする。**Rules のテストを書く** |
| Storage | 動画は `manager` 以上のみ read。`delete` は誰にも許可せずライフサイクルに任せる |
| 監査ログ | 誰がどの動画を見たかを記録する（`accessLogs`） |

**「見られる人」を技術的にも制限する。** 規程だけで運用すると、必ず崩れる。

---

## 5. AI 利用に関する取り扱い

- 文字起こしは Google Cloud（同一GCPプロジェクト内）
- カード起案・ボット回答は Claude API（Anthropic）へ送信される
- **どのデータが外部APIに送られるかを同意書に明記する**
- 送るのは文字起こしテキストとフレーム画像。**原本動画は送らない**
- 顔が明確に写るフレームは、必要がなければ送信対象から外す（作業手順の把握に顔は不要なことが多い）

---

## 6. 別 Firebase プロジェクトにする理由

契約管理システムとは**別プロジェクト**にする。

- 現場作業者のアカウントが契約データに到達しうる構成にしない
- 権限設計が単純になり、Rules のミスが起きにくい
- 監査時に「このプロジェクトには工場データしかない」と言える

---

## 7. 本番運用前チェックリスト

- [ ] 利用目的・保存期間・閲覧権限が文書化されている
- [ ] 同意書（日本語＋母語版）が用意され、全対象者から取得済み
- [ ] 同意しない人向けの代替手段が用意されている
- [ ] 就業規則または個別規程に記載済み
- [ ] Firestore/Storage Rules のテストが通っている
- [ ] Storage ライフサイクルルールが規程の保存期間と一致している
- [ ] 開示・削除請求の対応手順と担当者が決まっている
- [ ] 外部APIへ送信されるデータの範囲が同意書に明記されている
- [ ] 「フラグは違反認定ではない」が現場に説明済み
